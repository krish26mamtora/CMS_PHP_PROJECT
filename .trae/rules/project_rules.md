
🔧 Code Style & Structure
Use camelCase for variable names.

Use snake_case for function names.

Use PascalCase for class names.

Use UPPERCASE for constants.

Use lower_case for filenames, folders, and packages.

Maintain consistent indentation (e.g., 2 or 4 spaces; no tabs unless specified).

Use clear, meaningful names for variables, functions, and files.

Avoid code duplication — reuse logic through functions or includes.

🎨 Styling & Design Guidelines
Apply a consistent color scheme, typography, and spacing throughout the application.

Use standard CSS only (no Tailwind, Bootstrap, or third-party frameworks).

Maintain a responsive layout using media queries to support desktops, tablets, and mobile devices.

Avoid flashy, overly decorative, or distracting elements — prioritize clarity, usability, and a professional appearance.

For every .php file, place related CSS in the styles/ folder using a matching or relevant filename.

Create new .css files in the styles/ folder as needed.

💬 Form Handling & User Feedback
Prevent unnecessary page reloads after form submissions.

Avoid redirection to blank or unintended pages.

Provide clear and immediate user feedback after form submission (e.g., success, failure, validation messages).

Validate inputs both on the client-side (if applicable) and server-side.

🧠 Maintainability & Organization
Group related .php and .css files logically.

Keep file and folder structures clean and modular.

Include comments in complex logic blocks to aid understanding and future development.

Ensure error handling and fallback behaviors are present where needed (e.g., missing data, broken links).
